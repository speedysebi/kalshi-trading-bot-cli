# Trading bot readiness checklist

Status as of 2026-11-11: **unverified for live autonomy**. `Current` means a source path appears to implement part of the requirement; `Unknown` means no supplied run evidence proves it. Leave boxes unchecked until evidence and an owner are recorded. [Research report](reports/Trading%20bot%20readiness%20and%20Octagon%20replacement.md). Do not promote a gate on code presence alone.

## P0 — safety and accounting before live orders

- [ ] **Durable order lifecycle** — Current: V2 placement and optional `client_order_id` in `src/tools/kalshi/orders-v2.ts`; no verified complete intent ledger. Acceptance: persist unique intent before POST; require client ID; map exchange order ID, every fill `trade_id`, amend/cancel, fee, position, and settlement; replay duplicate/partial/unknown-ack/restart cases with no duplicate economic effect.
- [ ] **Safe ambiguous submission** — Current: `src/tools/kalshi/api.ts` retries POST failures. Acceptance: after timeout/429/5xx with uncertain result, query exchange order state by durable ID and reconcile before any resend; demonstrate this with fault injection.
- [ ] **Exchange reconciliation** — Current: local settlement sync in `src/tools/kalshi/settle.ts`; completeness unknown. Acceptance: on startup and after changes reconcile paginated orders, fills, positions, balance, and settlements across live/historical cutoffs; record zero unexplained differences; halt on mismatches or incomplete pages.
- [ ] **Fail-closed final risk gate** — Current: mandate in `src/risk/mandate.ts` returns zero daily loss on DB error; `src/risk/gate.ts` permits missing first drawdown snapshot. Acceptance: block new orders when DB, account, positions, resting orders, drawdown, model, quote, market status, or clock is stale/unknown; verify every order path invokes the same final gate.
- [ ] **Complete exposure limits** — Current: per-order caps and local-position checks; aggregate exchange exposure unknown. Acceptance: enforce precommitted per-order, per-market/event/series, aggregate worst-case resting-plus-held, daily realized/unrealized loss, and drawdown limits from reconciled exchange state; test correlated ladders and simultaneous orders.
- [ ] **Kill, cancel, and recovery** — Current: kill switch and cancel paths exist; end-to-end drill unknown. Acceptance: kill persists across restart, stops new risk immediately, permits cancel/flatten, and produces a complete incident record; test exchange outage and partial cancel acknowledgement.
- [ ] **Rights and contract review** — Current: no approved use matrix supplied. Acceptance: document Kalshi API/Data Terms applicability to storage, research, ML, and distribution; review each enabled series' full rules, settlement source, hours, fees, position limits, and trader eligibility; block unsupported or ambiguous markets.

## P1 — prove the strategy and its data

- [ ] **Freeze a point-in-time universe** — Current: `src/backtest/discovery.ts` uses Octagon coverage; historical universe completeness unknown. Acceptance: enumerate all eligible, excluded, missing, and dropped markets at each decision; store rule/version, availability and ingest timestamps, code/model version, and raw hashes in a versioned manifest.
- [ ] **Eliminate look-ahead** — Current: `src/backtest/fetcher.ts` checks snapshot capture date; source publication and bot availability unknown. Acceptance: replay sampled decisions solely from records with `available_at <= decision_at`, including source revision and pre-release boundary tests.
- [ ] **Executable replay** — Current: `src/commands/backtest.ts` enters at `market_probability`, defaults to no fee. Acceptance: price at contemporaneous executable side/depth; model spread, size, queue/latency, no/partial fills, series-specific historical fees, slippage, exit/settlement; label no-depth historical runs as assumed-fill.
- [ ] **Independent holdout and baselines** — Current: Brier, bootstrap, and baseline code in `src/backtest/metrics.ts`; untouched test results unknown. Acceptance: freeze rules and chronological splits by event, publish calibration/Brier/log loss against market and base rates, net P&L, uncertainty, drawdown, capacity, fee/fill sensitivity, and category/liquidity breakdowns; predefine minimum viable thresholds before viewing holdout.
- [ ] **Contract-correct labels** — Current: settlement fields and sync present; rule-source alignment unknown. Acceptance: archive full effective rules and source revision; verify outcome, early close/void/correction, payout and timing on a reviewed sample of every enabled contract family.
- [ ] **Shadow paper ledger** — Current: `src/commands/paper.ts` records requested price. Acceptance: log each decision, quote age, reject reason, achievable displayed price/size, hypothetical fill rule, fees, eventual result, and reconciliation to market history; report selection and no-fill counts.

## P1 — build the Octagon replacement in auditable layers

- [ ] **Exchange ingestion** — Current: signed client and historical calls under `src/tools/kalshi/`; no proven complete recorder. Acceptance: checkpoint cursor pagination and moving `/historical/cutoff` per data type; ingest market/event/series snapshots, rules, trades, candles, lifecycle, and settlement; count and alert on missing pages.
- [ ] **Prospective L2 collection** — Current: no verified historical depth archive or durable collector. Acceptance: start authenticated book/trade/lifecycle WebSocket capture in `src/daemon/` or `src/scan/`; retain raw envelopes, exchange and ingest time, sequence/gap markers, periodic REST snapshots, checksums, reconnect and resnapshot tests.
- [ ] **Point-in-time store** — Current: SQLite in `src/db/`; bulk research store unknown. Acceptance: immutable source observations, market/books/trades/candles, rules, cutoff snapshots, predictions, sim orders/fills and resolutions with provenance and rights tags; prototype Parquet + DuckDB with Bun; keep SQLite for live transactional ledger.
- [ ] **One authorized evidence adapter** — Current: Octagon report paths in `src/scan/`; independent estimate unverified. Acceptance: select one series family and record licensed authoritative historical inputs, exact release time, first-seen time, vintages/corrections, parser tests, and a simple probability baseline. Reject unsupported families.
- [ ] **Transparent scoring seam** — Current: `src/scan/octagon-client.ts`, `edge-computer.ts`, `loop.ts` couple scans to Octagon. Acceptance: provider-neutral prediction/evidence interface with model probability, uncertainty, market executable price, costs, liquidity, freshness, rules confidence, and risk decision; same versioned decision code runs in live/shadow/replay.
- [ ] **Remove Octagon dependence only after parity** — Current: `src/backtest/discovery.ts`, `fetcher.ts`, `src/scan/invoker.ts`, `octagon-*`, `src/tools/registry.ts` retain Octagon paths. Acceptance: native discovery and history are complete for selected series; report differences on an overlap set; update commands/help/TUI/README/e2e/gateway together for any changed flags or command signatures; preserve migration/replay provenance.

## P2 — operational evidence and staged deployment gates

- [ ] **Monitoring and audit** — Current: `src/audit/trail.ts`, DLQ, watchdog, and alerts exist; delivery/retention unknown. Acceptance: alert on stale data, auth/rate errors, stream gaps, DLQ growth, incomplete pagination, reconciliation differences, cap breaches, unacknowledged cancels, and daemon failure; drill alert receipt and response; reconstruct a sample trade from source through settlement; back up and restore audit and DB.
- [ ] **Secrets and release hygiene** — Current: local env/key support; production controls unknown. Acceptance: separate demo/live credentials and data, protected key storage, rotation/revocation and log redaction; pin dependencies, run `bun run typecheck`, `bun test`, and credentialed integration tests in an isolated environment; record release owner and rollback plan.
- [ ] **CI and release gate** — Current: `.github/workflows/ci.yml` calls a local Bun workflow for type safety, unit tests, and package contents; workflow linting and Actions updates are configured. `.github/workflows/release-tag.yml` requires a manual dispatch, while `publish-npm.yml` publishes a verified version tag. Acceptance: protect `main` with required CI and lint checks, review the npm dry-run inventory, approve each release, and verify a rollback/revocation procedure without putting live exchange credentials in public CI.
- [ ] **Gate 0: offline** — Acceptance: deterministic point-in-time replay, no held-out leakage, executable net-return report, and passing fault tests for unknown POST, duplicate/partial fills, stale state, outage, restart, cancel race, and settlement correction. No live submission.
- [ ] **Gate 1: live shadow** — Acceptance: continuous timestamped decisions and shadow ledger for a precommitted observation window; complete candidate/reject/fillability accounting; no unexplained data gaps; compare to achievable quotes and fees. No live submission.
- [ ] **Gate 2: demo** — Acceptance: demonstrate V2 create/amend/cancel, partial fills, restart, WebSocket/poll recovery, end-of-day reconciliation and operator halt with mock funds; zero unexplained ledger differences. Keep demo P&L separate from live evidence.
- [ ] **Gate 3: capped live pilot** — Acceptance: named operator, approved series/rights, documented small order/aggregate/daily-loss caps, reviewed exceptions, complete reconciliations, stable net results, and tested halt/restart. Increase caps only through a new evidence review.
